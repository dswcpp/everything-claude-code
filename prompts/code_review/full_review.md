## 审查维度

### 1. 代码质量
- 可读性：变量/函数命名是否清晰、自解释
- 代码结构：是否遵循单一职责原则（SRP）
- 代码风格：是否符合语言规范（如 C++ Core Guidelines、PEP8）
- 注释：关键逻辑是否有清晰注释

### 2. 潜在 Bug
- 逻辑错误：条件判断、循环边界
- 边界条件：空值、零值、极大/极小值
- 异常处理：是否有完善的错误处理和资源清理
- 并发问题：线程安全、竞态条件、死锁风险

### 3. 内存与资源
- 内存泄漏：是否正确释放资源
- 悬空指针/引用：生命周期管理
- RAII：是否使用智能指针（C++）
- 资源句柄：文件、网络连接是否正确关闭

### 4. 性能
- 时间复杂度是否合理
- 不必要的拷贝或重复计算
- 热路径是否优化
- 缓存友好性

### 5. 安全性
- 输入验证：是否过滤/转义用户输入
- 缓冲区溢出：数组边界检查
- 注入风险：SQL/命令注入
- 敏感信息：密码、密钥是否暴露

### 6. 最佳实践
- 是否符合该语言的惯用写法（Idiomatic）
- 是否遵循 SOLID 原则
- 是否便于单元测试
- API 设计是否合理
