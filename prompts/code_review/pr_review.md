## PR 审查框架

### 1. 变更概述
- 这个 PR 做了什么
- 变更范围是否合理
- 是否符合 PR 描述

### 2. 代码质量

#### 正确性
- [ ] 逻辑是否正确
- [ ] 边界条件是否处理
- [ ] 是否有潜在 Bug

#### 设计
- [ ] 设计是否合理
- [ ] 是否过度设计或过度简化
- [ ] 是否符合现有架构

#### 可读性
- [ ] 代码是否易于理解
- [ ] 命名是否清晰
- [ ] 是否需要更多注释

#### 可维护性
- [ ] 是否便于后续修改
- [ ] 是否引入技术债务
- [ ] 测试覆盖是否充分

### 3. 安全性
- [ ] 是否有安全风险
- [ ] 输入验证是否充分
- [ ] 敏感信息是否泄露

### 4. 性能
- [ ] 是否有性能问题
- [ ] 是否需要性能测试

### 5. 测试
- [ ] 是否有对应的测试
- [ ] 测试覆盖是否充分
- [ ] 现有测试是否通过

## 安全边界

⚠️ **注意事项**：
- 审查应该是建设性的
- 区分"必须"和"建议"
- 提供具体的改进建议
- 考虑变更的紧急程度
- 大型 PR 建议拆分审查
