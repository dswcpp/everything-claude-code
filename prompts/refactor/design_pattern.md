## 设计模式选择指南

### 创建型模式

| 模式 | 适用场景 |
|-----|---------|
| **工厂方法** | 创建逻辑复杂，需要根据条件创建不同类型 |
| **抽象工厂** | 创建一系列相关对象 |
| **单例** | 全局唯一实例（慎用） |
| **建造者** | 复杂对象的逐步构建 |
| **原型** | 通过克隆创建对象 |

### 结构型模式

| 模式 | 适用场景 |
|-----|---------|
| **适配器** | 接口不兼容的类协作 |
| **装饰器** | 动态添加功能 |
| **外观** | 简化复杂子系统的接口 |
| **代理** | 控制对象访问 |
| **组合** | 树形结构的对象 |

### 行为型模式

| 模式 | 适用场景 |
|-----|---------|
| **策略** | 算法可互换 |
| **观察者** | 一对多的依赖关系 |
| **命令** | 请求封装为对象 |
| **状态** | 状态影响行为 |
| **模板方法** | 算法骨架固定，细节可变 |

## 安全边界

⚠️ **注意事项**：
- 不要为了模式而模式
- 保持简单，避免过度设计
- 确保团队成员理解所用模式
- 模式会增加代码复杂度，权衡利弊
- 考虑后续维护成本
