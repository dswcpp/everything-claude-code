## 多文件重构原则

### 1. 渐进式重构
- 小步骤，每步可验证
- 保持代码始终可编译
- 每步重构后运行测试

### 2. 保持兼容
- 公共 API 不轻易改变
- 必要时提供兼容层
- 先增后删

### 3. 依赖管理
- 向稳定方向依赖
- 避免循环依赖
- 使用依赖注入

## 安全边界

⚠️ **注意事项**：
- 确保每个中间状态都可编译运行
- 提交应该是原子性的，每个提交完成一个逻辑步骤
- 保留足够的测试确保功能正确
- 重构期间不引入新功能
- 文档同步更新
